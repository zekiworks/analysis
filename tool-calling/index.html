How it is measured

Eight mock finance tools and 22 unrelated distractors. Six categories: single, selection, args, multi-step, restraint and recovery; seven pilot tasks each. At most eight total tool invocations per task.

Code checks exact tool names, normalised arguments, required call order and mock state. Wrong or extra state-changing calls fail; restraint requires no tool calls. We do not use an LLM judge.

Failure reasons: no_call, bad_format, template_bug, wrong_tool, wrong_args, extra_call, made_up_result, gave_up_or_loop. Verified serving/template failures remain unscored, never silent model zeroes.

After authorised runs, report three-repetition pass rates, categories and failure reasons, paired original/renamed and public/private comparisons, latency, tokens and documented cost. Only public per-task results may be exported. Pairwise sign-test tiers require real paired results within verified size classes.

Class uses official total parameters, active parameters separately; undisclosed models use the shared verified price classes. Requested names are not guessed into a class. Agent + harness measurements remain separate from bare-model results and require a fresh isolated fixture-only context.

Tool-calling scores in model cards are reported by the makers themselves; our model measurements will be run independently.
