Tasks

Each task is a short request from a user. The model sees the request and a list of tools, decides whether and how to call them, gets the tool results back and answers. A task passes only when the calls, their arguments and order, and the resulting account state are right; on restraint tasks, only when no tool is called. 42 tasks per track, 7 of each type, 3 repetitions each.

The 8 finance tools

  • get_price: The current price of a stock or coin (AAPL, MSFT, TSLA, BTC, ETH) in a chosen currency.
  • get_ohlc: Daily open, high, low and close prices for a date range.
  • get_balance: How much cash the paper account holds, per currency.
  • get_positions: How much of each stock or coin the paper account holds.
  • convert: Converts an amount between USD, EUR, GBP and JPY at fixed rates.
  • place_order: Places a dry-run buy or sell order (market or limit) on the paper account; nothing is traded.
  • cancel_order: Cancels an open dry-run limit order and releases the money or coins it held back.
  • search_news: Searches a fixed set of made-up headlines by text and date.

Decoy tools

22 tools that have nothing to do with finance (get_weather, list_calendar, search_email, translate_text, set_alarm, find_recipe, …). Some selection and restraint tasks offer all 30 tools, the 8 finance tools and the decoys together. They test whether the model still picks the right tool from a long list, and leaves an unrelated tool alone just because it is there.

Restraint tasks need no tool, or ask for something the tools cannot do. Recovery tasks hit a deliberate error (an unknown ticker, too little cash, a rate limit) and check that the model handles it as told.

Renamed tools

Every task also exists in a renamed version: the same request and the same tools, but every tool and argument has a neutral name (get_price becomes fetch_quote, symbol becomes ticker). A model that only recognises familiar names fails there; a model that reads the tool descriptions does not. Both versions are scored, and the Renamed tools tab shows them side by side.

Synthetic only

All data are fixed synthetic fixtures (prices, balances, news), "today" is 2026-11-12, and orders are dry runs on a paper account. Nothing touches a market or a real account, and no real trade is ever made.

Public files

31 of the 42 tasks per track are public; the other 11 stay private so the benchmark cannot be trained on. They count in the scores but are never published. Methodology

All tool observations use fixed synthetic finance fixtures, never real trades. Model answers are measured independently; tool-calling scores in model cards are maker-reported.

Original and renamed tracks are paired. Three repetitions per task; serving/configuration and verified template failures remain unscored. Public and private scores are separate; only public per-task details leave local storage.

Size class by total parameters, the same figures as the suite's other benches (from the maker's card, checked against the exact weights run): Tiny under 6B, Small 6B–15B, Medium over 15B up to 40B, Large over 40B.

No chance correction is applied. Tiers within each size class: for each pair of setups, every task (42 per track, public and private) is one paired item, won by the setup that passed more of its 3 repetitions; ties drop out. Exact two-sided sign test, Holm-corrected over all pairs of the class, p < 0.05. Rows in accuracy order: the top row starts Tier 1, and a row starts the next tier when the test separates it from its tier's top row. Accuracy: both tracks (84 tasks); Renamed tools: each track (42 tasks). – : not tiered (class not verified, incomplete or not qualified). Every pair's wins, losses, ties and p-values. Unknown cost and tokens stay unreported.
