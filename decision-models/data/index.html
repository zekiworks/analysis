Data

Everything the pages show comes from these files. They hold aggregate numbers and every answer, but not the questions: the publisher owns them.

FileContentsSize
results.jsonEvery published number: each setup's accuracy, confidence, latency and cost, and the routing replays and live tests.9.1 MB
answers.jsonEvery answer of every run, with its score and option probabilities, and the prompts. No question text.82.9 MB
picks.jsonBuilt from answers.json for these pages: each leaderboard setup's pick and score on each scored question, and each Turkish vs English model's English pick and score on each kept reading question.1.5 MB
vision.jsonThe page-image track: the questions that depend on the printed page, asked as text, as page images and through OCR; every number and each answer's pick and option probabilities. No question text, page image or OCR text.10.4 MB
vision-repeats.jsonThe page-image track's repeat passes, kept outside its table: each pass's run records and answers, compared with the table's first pass.1.4 MB
english-reading.jsonThe Turkish vs English track's record: the translator, its two prompts, each reading question's flags and the SHA-256 of its English text. No question text.120 kB
web-grounding.jsonThe web grounding experiment's inputs beside answers.json: each run's input tokens by group, what the grounded searches returned (sites and source checks, as counts and question IDs) and PWS-Decisions' aggregates. No question text, page address or snippet.21 kB

Results version 2522aafa (what changed: the results changelog); picks.json 772c98d8ef27. The code that ran the benchmark and rebuilds these files is in the repository; its runner README explains how someone who owns the book rebuilds the question bank.

Every setup in this benchmark is scored on one frozen answer key. This file lists every change to that key.

How a fix works. A fix to the key needs a check against the book's own key, or a second person who reviews the question and its options without seeing the models' answers. Each fix creates a new key version, adds a row to this file (question ID, old answer, new answer, reason, date) and rescores every run.

To report a wrong key, see CONTRIBUTING.md.

How to identify a version. results.json names the key version under answer_key, with the SHA-256 of the question bank and the key's fingerprint: the SHA-256 of [[id, key, excluded], ...] over every question in answers.json, as compact JSON in question order (answer_key_fingerprint in benchmark_metrics.py).

reproduce.py recomputes the fingerprint and checks every exported answer against the key. export_results.py stops when the answers are graded against a key that is not frozen there.
