Answer key changelog

Every setup is scored on answer key version 2. Question bank SHA-256 797ad6c868bc1c9485bc54203f58839ad995b0443b7149f6a9e36cf0d07df4d7; key fingerprint cd7f998de262e355cd28f596465a51f4158211646ee0cbfbc85f5d8cdeced20a.

Every setup in this benchmark is scored on one frozen answer key. This file lists every change to that key.

How a fix works. A fix to the key needs a check against the book's own key, or a second person who reviews the question and its options without seeing the models' answers. Each fix creates a new key version, adds a row to this file (question ID, old answer, new answer, reason, date) and rescores every run.

To report a wrong key, see CONTRIBUTING.md.

How to identify a version. results.json names the key version under answer_key, with the SHA-256 of the question bank and the key's fingerprint: the SHA-256 of [[id, key, excluded], ...] over every question in answers.json, as compact JSON in question order (answer_key_fingerprint in benchmark_metrics.py).

reproduce.py recomputes the fingerprint and checks every exported answer against the key. export_results.py stops when the answers are graded against a key that is not frozen there.
