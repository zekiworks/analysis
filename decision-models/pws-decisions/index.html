Our method

Each question went out as PWS-Decisions' own request (its state, and one choice question with its instructions and its choices), with the setup's model name, to the same API and endpoint as the setup's Text tab run. OpenAI's Decisions API takes the same parts under its own names. One question per request, each provider's requests one after another, the providers at the same time. Timeout 60 s; the runner's retries (up to 5, on 408, 425, 429 and 5xx, and transport failures). Scored with PWS-Decisions' own scorer: a refusal, an error or an invalid answer counts as wrong.

  • Request time: from sending a request to its answer, retries included, over the requests that got an answer; the median and the 95th percentile by nearest rank.
  • The chance line, 44.67%: the mean over the 100 questions of 1 / the number of choices, (77 × 1/2 + 5 × 1/3 + 18 × 1/4) / 100.
  • The 95% interval: 10,000 resamples of the 100 questions with replacement (seed 20261105), each question scored as the mean of its 3 runs' correctness (a missing answer is wrong); the 2.5th and 97.5th percentiles of the resampled accuracy. It is the uncertainty from the question sample; the lowest to highest run is the run-to-run range.
  • Liquid d1 was asked as d1: Liquid's API no longer serves the d1:free name of its Text tab run.
  • Perplexity's own figures: 86% with web on these questions, with 370 ms at the median and 685 ms at the 95th percentile from Perplexity's client (Web grounding for the Decisions API, 4 November 2026); the 51% without is Parallel's leaderboard figure.
