About the Reading bench

Our reading comprehension and grammar test: 2,198 questions answered by 52 decision models, with chat models for comparison. A decision model scores each answer option and picks one. Grammar questions test whether a model knows a rule and can apply it. Every answer is public.

The questions come from a published book; their text stays unpublished, as the publisher owns it. Every setup's answer to every question is in answers.json. The Method page has the full study: the questions, the answer key, the runs and the tests.

How the scores work

  • What is scored. 2,198 questions written in Turkish, not translated: 656 reading and 1,542 grammar. Each answer is right or wrong against the answer key; an invalid answer counts as wrong.
  • How models answer. A decision model scores each answer option and picks one, with a confidence for it. A chat model gets the question and its options in a prompt and replies with the letter of its answer.
  • What a setup is. One model with one setting: its reasoning level, how many questions go in one request (1 or 16), where it ran (a provider's API, a subscription or our GPUs) and whether it searched the web. 99 setups: 52 decision-model and 47 chat-model setups.
  • How differences were tested. Paired tests on the same questions, with Holm's correction for the number of comparisons. Setups that share a letter in the ranking were not told apart by the paired test.
  • What cost means. An estimate in dollars per 1,000 questions, not a bill: list prices and recorded token use for API setups; for our GPUs, a list price for the same model or weights, or the GPU time.

The rest is on the Method page.

Notes behind the scores

Ranks show observed scores; small gaps need not be meaningful.

Costs: API list prices and recorded token use. Setups on our own GPUs: the maker's list price for the same model (each value's tooltip names it); our hardware cost is not measured. On our GPUs with no public price for the same weights, estimated from GPU time: the run's request time x the GPUs its server held x Runpod's on-demand price for an RTX PRO 6000, $2.49 per GPU-hour (read 5 November 2026): a cloud-equivalent estimate, not measured spending. No list price: on our own GPUs, with no estimate. ≤ Upper-bound estimate: one $0.001 web search counted per request; Perplexity bills only completed searches. * Measured on a sample (200 questions).

The leaderboard rules

Row rule: each model's highest reasoning setting (none, off or the chat template's default < minimal < low < medium < high < xhigh < max; on above off for a model with only on and off); a decision model has no setting. Tie-break: several setups at that setting give the row to the earliest run (the lowest run id), never to the higher score. A model with one setup uses it. Every value of a row and of its details box comes from that one chosen setup; its other setups are under the row's expander and under All setups. A setup with web search is its own row; different version names are separate rows; a dated checkpoint joins another model's row only through the map below, never by a similar name.

The dated-checkpoint map (page_config.json, leaderboard.dated_checkpoints), the only model IDs listed under another: deepseek-v4.1-flash-1017 is listed under deepseek-v4.1-flash, by this map. The row shows the original; the checkpoint's setups sit under its other settings.

Ranks show observed scores; small gaps need not be meaningful. The type keys (All, Chat models, Decision models) and the Class keys (Tiny, Small, Medium and Large for an open model by its total parameters; Efficient, Workhorse and Flagship for a closed model, or an open one of undisclosed size, by its list price per 1M input tokens) choose the rows in view; the setups only this site ran are in no class and show under Class: All. On the Turkish part the Tier column holds each row's tier among the rows in view: ranked by accuracy, a row joins the tier of the tier's top row when the all-pairs test behind the full ranking's letters found no difference between them, else it starts the next tier. On Turkish reading, Turkish grammar, English reading and Both, which no all-pairs test covers, the Rank column holds the row's place, 1, 2, 3 without repeats; rows with the same score keep the table's order, which claims no difference. Each row names its model by its official name, with a small tag beside it for how the setup ran (setting · route · snapshot, as “high · chat” or “API · with web”; a decision model with one setup has none), then its class label, starting Open or Closed; its details box gives the size in full and the model page its source.

Each bar runs from 0 to 100%; its whisker is the Wilson 95% interval of the accuracy, the interval each setup's page gives. The paired tests behind the full ranking's letters are on Method.

Not measured or "Not run" in a column: the setup has no such value; the details box leaves such a line out.

Hallucination

A wrong answer counts as a hallucination: the model could have chosen “I don't know” instead. This tab is separate from the leaderboard; it ranks nothing on the Text tab and changes none of its numbers.

With “I don't know”, no difference in wrong answers between the option and confidence is significant. With “I don't know” in place of “I don't know”, d1-ultra’s own confidence left significantly fewer wrong answers than “I don't know” did; for the other 6 models that used it, the difference could be chance (What we found).

PWS-Decisions

PWS-Decisions is Parallel Web Systems' benchmark of 100 public English multiple-choice questions whose answers depend on dated facts on the public web. We asked 38 decision model setups and 28 chat model setups that an API still serves, 3 runs each, one question per request. With web search: GPT-6.1 Sol · high · chat · CLI · with web, Gemini 4 Argon · low · chat · with web, GPT-6 Astra · high · chat · CLI · with web, Claude Fable 5.1 · high · chat · CLI · with web · 2 requests handed to Claude Opus 4.8, counted wrong, GPT-6.1 Terra · high · chat · CLI · with web, Gemini 3.8 Flash · high · chat · with web, Grok 4.7 · high · chat · with web, Claude Opus 5.5 · high · chat · CLI · with web, Claude Sonnet 5.5 · high · chat · CLI · with web, Perplexity Decider 27B v1.2 · API · with web and GPT-6 Luna · low · chat · CLI · with web; every other setup answered without search. This page is not part of the Turkish ranking.

What this measures. Parallel Web Systems made PWS-Decisions. This is an end-to-end comparison of API setups with and without web search on its 100 public questions, which Parallel chose “for their difficulty and alignment with customer outcomes” (its methodology), around its customers' needs for current facts from the web. It is not a general ranking of models: without search, most setups score near random guessing, because the answers depend on dated web facts they were not given.

53 setups have a mean accuracy above the 44.7% chance line (Parallel's random-guess baseline, not a run of ours); every accuracy here is the mean of our 3 runs.

Summary

No decision model led on every measure:

  • Accuracy: KnowLine-31B-Gen1.5 clearly ahead at 81.8%; REAX 1.3, Gemini Decision 1 and Liquid's d1-ultra, tied at 77.9%, 77.5% and 77.1%; GLiDE 27B at 71.1%; then Decider v1.2 with web search, GLiDE v1.2, hosted GLiDE, d3 and d3-ultra, Drex Max and Drex Max v1.1, Mammoth-1, Decider v1.1 and Decider v1.2 on our DGX Spark, at 66.9% to 68.7%.
  • Calibration gap, as shipped: d1.1 had the smallest among decision models.
  • Better than a flat guess, after refit: hosted Perplexity Decider 27B v1.2 at 32.1%, then Open-Jev-27B-v1.1 (31.9%), then SubQ Snap 1.1 and Perplexity Decider 27B v1.1 (31.5% each); the gaps are untested.
  • Estimated saving: d1-ultra, the biggest in 7 of 16 LLM setups; Gemini Decision 1 in 5; REAX 1.3 in 2; GLiDE 27B in 2.
  • Reading vs grammar: decision models got up to 92.8% of reading questions right, but at most 77.1% of grammar.
